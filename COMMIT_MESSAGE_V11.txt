feat: V11 ID-Based Response Format Refactor - Eliminuje first/second confusion

PROBLÉM:
1. Sleep animation bug: Blocked attacks zobrazovali attack s 0 damage namiesto blocking animácie
2. Confusing kód: isCard1First, card1, card2, firstCard, secondCard vyžadovali mentálnu mapu
3. Bug v response: blocked: false napriek blockedBy: 3 a server logs: secondResult.blocked = true
4. Hardcoded assumption: První útočník nikdy nie je blocknutý (falošný predpoklad)

ROOT CAUSE:
Pozičné identifikátory (first/second/1/2) vytvárali confusion:
- Server používal isCard1First ternary logic → mentálna záťaž
- Response mal attacks[card1_uuid] dictionary → nejasná sémantika
- damage field bol ambiguózny → damage received alebo dealt?
- Hardcoded: card1.blocked = isCard1First ? false : secondResult.blocked

User feedback:
> "cely cas vo vsetkych vlaknach hovorim aby sa veci neidentifikovali ako first a second ale podla id"

RIEŠENIE: ID-Based Response Format

Server (executeBattle.js):
- ✅ Case 1 (both blocked): Priame role assignment (firstAttacker/secondAttacker)
- ✅ Case 2 (first blocked): Clear damage flow (damageReceived/damageDealt)
- ✅ Case 4 (normal battle): Odstránená isCard1First logika
- ✅ Všetky cases: Jasná sémantika (what I took vs what I gave)

Client (BattleResultProcessor.cs):
- ✅ Parsing: Extrakcia firstAttacker/secondAttacker objektov
- ✅ Role detection: iAmFirstAttacker = (firstAttackerCardId == myCardId)
- ✅ Data access: myAttackData/enemyAttackData (jedna boolean pre všetko)
- ✅ Method signatures: firstAttacker → firstAttackerCardId (jasné ID)
