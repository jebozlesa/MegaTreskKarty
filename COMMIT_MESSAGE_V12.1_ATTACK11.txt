V12.1: Attack 11 (Scientific Lecture) - Server-Driven Architecture

FEATURES:
✅ Attack 11 (Scientific Lecture) implementation
   - Knowledge-based RNG attack (50% success rate)
   - 3 possible outcomes: impressed (+1 Knowledge), bored (Sleep), blocked
   - Server explicitly decides outcome via `attackResult` field
   
✅ Server-Driven Architecture Pattern
   - Server returns `attackResult` field with explicit outcome string
   - Client is "dumb renderer" - no game logic, only animation routing
   - Scales cleanly for attacks with 3+ outcomes
   - Pattern template for future complex attacks (12-123)

✅ AttackStatChanges Struct (12 fields)
   - Clean replacement for 16-parameter function signatures
   - 6 attacker buffs (self-buffs like WaterToWine, ScientificLecture)
   - 6 defender debuffs (debuffs on enemy like Crusade, ScientificLecture)
   - Passed as single object through coroutine chain

✅ Stat Change Timing Fix
   - ALL stat changes display DURING attack turn (after ExecuteAttackAnimation)
   - Fixed 4 code paths: first/second attacker, my/enemy turn
   - Knowledge buff shows immediately after attack animation, not in RefreshCards
   - "z pohľadu hráča sa nemá na konci kola diať nič" ✅

✅ Sleep/Knockout Effect Separation
   - Sleep (ID 3): Boredom-induced, NO KO animation (already shown during attack)
   - Knockout (ID 27): Physical knockout (Punch, Car Hit), WITH KO animation
   - Attack 11 (Scientific Lecture) uses Sleep (ID 3)
   - Attack 1 (Punch) now uses Knockout (ID 27)

🐛 "Something went wrong" when attacker blocked
   - Problem: attackResult was null when attacker had blocking effect → default case

   - Fix: Added null check in Attack11Handler, show "no effect" gracefully
   - File: Attack11Handler.cs lines 25-32

🐛 Lecture animation skipped when blocked
   - Problem: Early exit before lecture animation when attackResult was null
   - Impact: No visual feedback that attack was attempted
   - Fix: Moved null check AFTER lecture animation, show attempt then "no effect"
   - File: Attack11Handler.cs - reordered flow

🐛 ExecuteAttackAnimation missing in first attacker block
   - Problem: Accidentally removed during stat changes refactoring
   - Impact: No attack animation when player attacks first

   - File: BattleResultProcessor.cs line ~728

🐛 Wrong animation (Impressed instead of Bored)
   - Problem: ExecuteAttackAnimation called without myEffectsApplied parameter

   - Fix: Added myEffectsApplied to all 4 ExecuteAttackAnimation call sites
   - File: BattleResultProcessor.cs lines ~728, ~735, ~948, ~1052

PRINCIPLES FOLLOWED:
🎯 "Klient má byť len hlúpy renderer"
   - Server decides ALL game logic (RNG, blocking, outcomes)
   - Client only displays what server tells it
   - No IF logic checking effectsApplied to guess outcome

🎯 "to co sa deje s kartou by sa malo diať na základe IDčka karty"
   - Card ID based system
   - No first/second player distinctions in attack logic
   - Works independently of attack order

🎯 "vsetky akcie súvisiace s útokom hráča sa dejú počas jeho tahu"
   - Knowledge buff displays during attack turn
   - Sleep icon displays during attack turn
   - Nothing happens in RefreshCards from player perspective

🎯 "z pohľadu hráča sa nemá na konci kola diať nič"
   - All visible effects happen during attack animations
   - RefreshCards only syncs state, no new visual changes
